ordito.smoothing

Laplacian smoothing filters, for vertex positions and for per-vertex scalar fields.

Most of the module moves geometry: filter_laplacian, filter_taubin, filter_humphrey, filter_neighborhood_average, filter_mut_dif_laplacian and filter_implicit_fairing all diffuse vertex positions through the same row-stochastic 1-ring operator, differing in the time integration and in what they do to counteract shrinkage. smooth_region and its sharp-boundary variant instead solve a Dirichlet problem over a region, holding the rest of the mesh fixed.

Three functions work on the normal field instead of positions, which is what lets them keep a crease sharp: filter_normals diffuses face normals with a crease gate, filter_two_step then refits the vertices to them, and filter_sharpen runs the whole idea backwards to sharpen.

A second group relaxes toward something other than a Laplacian residual, which is what lets each member fix a failure the filters above cannot see: equalize_triangle_areas evens out triangle areas, relax_keep_volume removes the shrinkage locally instead of rescaling it away at the end, relax_approx fits a plane or a quadric to a whole geodesic neighbourhood rather than averaging a 1-ring, and filter_spikes moves only the vertices that fail an angle test. The first three take a vertex region and a max_displacement bound, so a relaxation can be confined to where it is wanted and kept within a tolerance of the surface it started from; filter_spikes needs neither, because the set it touches is the answer to its own test. smooth_region_boundary completes the region trio by smoothing the region's rim curve, where the two above it smooth across the rim or inside it.

The verb tracks the mechanism, not the group. filter_* runs a fixed operator to a schedule -- an assembled Laplacian, a normal-field pass, a windowed Taubin pair -- so the answer is a function of the operator and the iteration count. relax_* iterates against a geometric objective and re-derives its target every pass, which is why those take a max_displacement bound: nothing in the mechanism keeps the result near the input. equalize_triangle_areas and smooth_region* name their objective outright because there is only one of each. By that axis filter_spikes is correctly a filter_*: it runs the same fixed 1-ring operator, and only its selection is geometric.

filter_scalar_laplacian runs the same operator over a per-vertex scalar field rather than positions. Capping how fast such a field may vary along an edge -- the other half of turning a raw scalar into a usable sizing field -- is not a smoothing filter at all but a one-sided Lipschitz projection, and lives in shortest_path_envelope.

Laplacian mesh smoothing (Vollmer et al.; Desbrun et al. implicit fairing).

Diffuses each vertex toward the mean of its 1-ring neighbors. With implicit_time_integration the diffusion is solved implicitly (backward Euler, unconditionally stable); otherwise an explicit forward-Euler step is used (stable for lamb <= 1). Mirrors trimesh.smoothing.filter_laplacian but returns a new vertex array instead of mutating the mesh in place.

method="pyvista" moves the vertices one at a time instead, in index order, each toward the mean of its neighbours as they stand, so a vertex sees the lower-numbered ones already moved in the same pass (a Gauss-Seidel sweep): VTK's vtkSmoothPolyDataFilter (pyvista.PolyData.smooth) with relaxation_factor=lamb and n_iter=iterations, without feature-edge smoothing. The answer depends on the vertex numbering, as VTK's does; the passes run in parallel on CUDA all the same.

def filter_laplacian(
    vertices: wp.array[wp.vec3],
    faces: wp.array[wp.int32],
    lamb: float = 0.5,
    iterations: int = 10,
    implicit_time_integration: bool = False,
    volume_constraint: bool = True,
    laplacian_operator: odt.BsrMatrix[wp.float32] | None = None,
    *,
    method: Literal["jacobi", "pyvista"] = "jacobi",
    edge_angle: float = 15.0,
    rim_smoothing: bool = True,
) -> wp.array[wp.vec3]:
    """
    Laplacian mesh smoothing (Vollmer et al.; Desbrun et al. implicit fairing).

    Diffuses each vertex toward the mean of its 1-ring neighbors. With ``implicit_time_integration``
    the diffusion is solved implicitly (backward Euler, unconditionally stable); otherwise an
    explicit forward-Euler step is used (stable for ``lamb <= 1``). Mirrors
    [`trimesh.smoothing.filter_laplacian`][] but returns a new vertex array instead of mutating
    the mesh in place.

    ``method="pyvista"`` moves the vertices one at a time instead, in index order, each toward
    the mean of its neighbours as they stand, so a vertex sees the lower-numbered ones already
    moved in the same pass (a Gauss-Seidel sweep): VTK's ``vtkSmoothPolyDataFilter``
    (``pyvista.PolyData.smooth``) with ``relaxation_factor=lamb`` and ``n_iter=iterations``,
    without feature-edge smoothing. Its neighbours are VTK's: the whole 1-ring of an interior
    vertex; for a vertex on a rim edge or an edge of three or more faces, its two neighbours along
    such edges, unless there are not exactly two, the path through them turns by more than
    ``edge_angle``, or (on a rim) ``rim_smoothing`` is off, in which case it stays fixed. The
    answer depends on the vertex numbering, as VTK's does; the passes run in parallel on CUDA all
    the same.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    lamb
        Diffusion speed. ``0`` leaves the mesh unchanged; larger values smooth faster.
    iterations
        Number of smoothing passes.
    implicit_time_integration
        If ``True`` solve ``((1 + lamb) I - lamb L) V' = V`` each pass. The system is strictly
        diagonally dominant for a row-stochastic ``L``, so it is solved by a fixed-point iteration
        whose step count follows from ``lamb`` and ``L``'s row sums -- ``L`` is not symmetric on a
        mesh with a boundary, so a symmetric Krylov method does not apply -- falling back to
        BiCGSTAB when that count is large or ``L`` is not a contraction. If ``False`` apply the
        explicit step ``V' = V + lamb (L V - V)``. An unreferenced vertex, whose row of ``L`` is
        empty, stays where it is on both paths.
    volume_constraint
        If ``True`` rescale the mesh after each pass to preserve its initial volume, counteracting
        Laplacian shrinkage.
    laplacian_operator
        ``(n_vertices, n_vertices)`` optional precomputed row-stochastic operator (see
        [`laplacian`][ordito.laplacian.laplacian]). Autogenerated (uniform weights) when ``None``.
        Must be ``None`` under ``method="pyvista"``, whose neighbours are its own.
    method
        The update.

        - ``"jacobi"`` (default) — every vertex at once, from the previous pass's positions.
        - ``"pyvista"`` — vertex by vertex in index order, VTK's (see above). Explicit only.
    edge_angle
        Under ``method="pyvista"``, the largest turn, in degrees, of the path through a rim or
        crowded vertex's two neighbours that still lets it slide along them. Unread otherwise.
    rim_smoothing
        Under ``method="pyvista"``, slide rim vertices along the rim; when off they stay fixed
        (VTK's ``boundary_smoothing``). Unread otherwise.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` smoothed vertex positions on ``vertices.device``.

    Raises
    ------
    ValueError
        If ``method`` is not ``"jacobi"`` or ``"pyvista"``, or under ``method="pyvista"`` if
        ``implicit_time_integration`` is set or ``laplacian_operator`` is given.
    RuntimeError
        If ``vertices`` and ``faces`` are not all on one device.

    See Also
    --------
    [`filter_taubin`][ordito.smoothing.filter_taubin]
    [`filter_humphrey`][ordito.smoothing.filter_humphrey]
    [`filter_implicit_fairing`][ordito.smoothing.filter_implicit_fairing]
    [`trimesh.smoothing.filter_laplacian`][]

    Examples
    --------
    Plain Laplacian smoothing shrinks a closed surface; the default volume constraint rescales
    it back:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    shrunk = od.smoothing.filter_laplacian(vertices, faces, volume_constraint=False)
    print(od.measures.volume(shrunk, faces) < od.measures.volume(vertices, faces))  # True
    kept = od.smoothing.filter_laplacian(vertices, faces)
    print(f"{od.measures.volume(vertices, faces):.3f}")  # 4.153
    print(f"{od.measures.volume(kept, faces):.3f}")  # 4.153
    ```

    VTK's in-place sweep moves a vertex further per pass than the simultaneous step, so the
    surface shrinks faster:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    jacobi = od.smoothing.filter_laplacian(vertices, faces, volume_constraint=False)
    sweep = od.smoothing.filter_laplacian(
        vertices, faces, volume_constraint=False, method="pyvista"
    )
    print(od.measures.volume(sweep, faces) < od.measures.volume(jacobi, faces))  # True
    ```
    """
    require_same_device(vertices=vertices, faces=faces)
    if method not in ("jacobi", "pyvista"):
        raise ValueError(f"method must be 'jacobi' or 'pyvista', got {method!r}")
    if method == "pyvista" and implicit_time_integration:
        raise ValueError("method='pyvista' is explicit: implicit_time_integration must be False")
    if method == "pyvista" and laplacian_operator is not None:
        raise ValueError(
            "method='pyvista' builds its own neighbours: laplacian_operator must be None"
        )
    # This six-line prologue is shared by five of the filters (here, ``filter_humphrey``,
    # ``filter_taubin``, ``filter_neighborhood_average`` and ``filter_mut_dif_laplacian``), but a
    # shared helper is not worth it: the two halves have no common consumer.
    # ``filter_implicit_fairing`` needs the guard and ``_as_vec3d`` but builds no operator,
    # ``filter_neighborhood_average`` needs the operator built ``symmetric=True``, and a helper
    # returning both would have to hand back an optional operator that three of the six callers
    # immediately unwrap.
    device = vertices.device
    n = vertices.size
    if n == 0 or iterations == 0:
        return _launch.clone(vertices)
    if method == "pyvista":
        return _gauss_seidel_passes(
            vertices, faces, lamb, iterations, volume_constraint, edge_angle, rim_smoothing
        )

    operator = _resolved_operator(vertices, faces, laplacian_operator)
    coeff = wp.float64(lamb)
    if not implicit_time_integration and not volume_constraint:
        # Explicit passes with nothing between them: the first reads the ``float32`` input and the
        # last writes the ``float32`` answer.
        return _vec3_passes(
            vertices, iterations, lambda _index, src, dst: _diffuse_pass(operator, coeff, src, dst)
        )
    steps = _implicit_fixed_point_steps(operator, lamb) if implicit_time_integration else None
    # With nothing to anchor, the fixed-point passes start from the ``float32`` input itself: the
    # first pass reads it widened as each entry is read, and its last step writes the ``float64``
    # iterate, so no widening copy is made.
    widen_on_read = steps is not None and not volume_constraint
    positions = (
        _launch.empty(n, dtype=wp.vec3d, device=device) if widen_on_read else _as_vec3d(vertices)
    )
    # The *initial* volume and centre of mass, captured once here rather than inside the loop --
    # see ``kernel_smoothing.volume_rescale_parameters`` for why the rescale has to stay anchored to
    # this one fixed point rather than the mesh's current (already-moved) centre of mass.
    constraint = (
        _VolumeConstraint.anchored(positions, vertices, faces) if volume_constraint else None
    )

    if steps is not None:
        # ``(1 + lamb) I - lamb L`` is strictly diagonally dominant for a row-stochastic ``L``, so
        # the fixed-point iteration converges at a rate known in advance, symmetric or not -- and
        # the uniform operator is *not* symmetric on a mesh with a boundary, which conjugate
        # gradient needs. So each pass is a fixed number of fused launches with no reduction and
        # no convergence test, the same launch sequence every pass: issued once, then recorded and
        # replayed where the device has graphs.
        scratch = [_launch.empty(n, dtype=wp.vec3d, device=device) for _ in range(2)]
        graph = None
        for index in range(iterations):
            if graph is not None:
                wp.capture_launch(graph)
            elif index > 0 and wp.get_device(device).is_cuda:
                with wp.ScopedCapture(device) as capture:
                    _implicit_fixed_point_pass(operator, coeff, steps, positions, scratch)
                graph = capture.graph
                assert graph is not None
                wp.capture_launch(graph)
            else:
                source = vertices if widen_on_read and index == 0 else None
                _implicit_fixed_point_pass(operator, coeff, steps, positions, scratch, source)
            if constraint is not None:
                constraint.apply(positions)
    elif implicit_time_integration:
        # The fixed-point step count past its cap, or an operator that is not a contraction: solve
        # the assembled system instead, with a Krylov method that does not need it symmetric --
        # conjugate gradient on this system diverges on a mesh with a boundary at a large ``lamb``.
        system = _build_implicit_system(operator, lamb, n, device)
        preconditioner = wpl.preconditioner(system, "diag")
        components = _component_columns(n, device)
        solutions = _component_columns(n, device)
        component_rows = [odt.as_dense(components[column]) for column in range(3)]
        solution_rows = [odt.as_dense(solutions[column]) for column in range(3)]
        for _ in range(iterations):
            _launch.map(kernel_smoothing.extract_components, positions, out=component_rows)
            # Seeded with the right-hand side, which is the current position component.
            _launch.copy(solutions, components)
            for column in range(3):
                wpl.bicgstab(
                    system,
                    component_rows[column],
                    solution_rows[column],
                    tol=twl.CG_TOLERANCE,
                    atol=0.0,
                    maxiter=10 * n,
                    M=preconditioner,
                )
            _launch.map(
                kernel_smoothing.combine_components,
                solution_rows[0],
                solution_rows[1],
                solution_rows[2],
                out=positions,
            )
            if constraint is not None:
                constraint.apply(positions)
    else:
        # Explicit passes, each rescaled to the anchored volume; the last rescale writes the
        # ``float32`` answer.
        assert constraint is not None
        nxt = _launch.empty(n, dtype=wp.vec3d, device=device)
        for index in range(iterations):
            _diffuse_pass(operator, coeff, positions, nxt)
            positions, nxt = nxt, positions
            if index == iterations - 1:
                out = _launch.empty(n, dtype=wp.vec3, device=device)
                constraint.apply(positions, out=out)
                return out
            constraint.apply(positions)

    return _as_vec3(positions)

    Inflate a surface under uniform pressure: normal displacement alternating with smoothing.

    The "balloon" flow. Each pass moves every vertex along its own
    [`vertex_normals`][ordito.vertices.vertex_normals] at ``weighting="area"`` and then relaxes
    with one Laplacian pass, which is what keeps the triangles from shearing as the surface grows.

    Like any displacement along vertex normals it can fold the surface at a sharp vertex, one with

    something intrinsic -- a fraction of the mean edge length is the usual choice. With ``gradual``

    gentler on a mesh with fine triangles: the early passes let the relaxation redistribute
    before the later ones push hard.

    !!! note "Not the implicit formulation"
        The reference inflations displace and then solve an *implicit* Laplacian system, where
        this runs one explicit pass -- so the two produce different surfaces from the same
        ``pressure``, and the tests compare the properties an inflation must have (volume grows,
        the displacement is normal-aligned) rather than positions. Pass the result through
        [`filter_implicit_fairing`][ordito.smoothing.filter_implicit_fairing] if you want that
        formulation; it costs a conjugate-gradient solve per pass, which is why it is not the
        default here.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    pressure
        Distance to move along the normal per pass. Negative deflates.
    iterations
        Number of displace-and-relax passes.
    pre_smooth
        Run one relaxation pass *before* the first displacement. Worth it on a noisy input, where
        the normals are what the noise corrupts and displacing along them amplifies it.
    gradual
        Ramp the pressure linearly across the passes instead of applying it in full each time.
    lamb
        Relaxation strength of each Laplacian pass, as
        [`filter_laplacian`][ordito.smoothing.filter_laplacian] takes it.
    vertex_faces
        ``(3 * n_faces,)`` and ``(n_vertices + 1,)`` optional precomputed
        [`vertex_face_adjacency`][ordito.adjacency.vertex_face_adjacency] as
        ``(vertex_faces, offsets)``. Depends on the connectivity alone -- which this flow never
        changes -- so one CSR serves every call over the same mesh, and
        [`Trimesh.vertex_face_adjacency`][ordito.mesh.Trimesh.vertex_face_adjacency] has it cached.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` inflated positions on ``vertices.device``. The connectivity is untouched,
        so ``faces`` remains valid.

    Raises
    ------
    ValueError
        If ``iterations`` is negative.
    RuntimeError
        If ``vertices``, ``faces`` and ``vertex_faces`` are not all on one device.

    See Also
    --------
    [`offset_mesh`][ordito.levelset.offset_mesh]
        The *exact* outward offset, through a signed distance field -- it changes the connectivity
        and cannot self-intersect, where this keeps the mesh and can.
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]
        The relaxation half of each pass.

        Turns a surface into a solid shell, which is the other way to give it thickness.

    Examples
    --------
    A positive pressure grows a sphere:

    ```python

    inflated = od.smoothing.inflate(vertices, faces, 0.05)
    print(od.measures.volume(inflated, faces) > od.measures.volume(vertices, faces))  # True
    ```

    require_same_device(vertices=vertices, faces=faces, vertex_faces=vertex_faces)
    if iterations < 0:
        raise ValueError(f"iterations must be non-negative, got {iterations}")
    device = faces.device
    n_vertices = vertices.size
    if n_vertices == 0 or faces.size == 0 or iterations == 0:
        return _launch.clone(vertices)

    # The relaxation operator is built once: ``filter_laplacian`` builds the uniform operator per
    # call, and at ``equal_weight=True`` that operator is the mesh's topology, which no pass
    # changes.
    operator = laplacian.laplacian(vertices, faces)
    # Each pass is the displacement and then one ``filter_laplacian`` pass with its volume
    # constraint, written out so that nothing is allocated per pass: the displacement gathers each
    # vertex's normal over the vertex-face table built once here, and every buffer and the
    # constraint's device state are reused. Same arithmetic as the composed calls, up to the
    # normal sums' order.
    vf_indices, vf_offsets = (
        vertex_faces
        if vertex_faces is not None
        else od.adjacency.vertex_face_adjacency(faces, n_vertices=n_vertices)
    )
    positions = _launch.empty(n_vertices, dtype=wp.vec3, device=device)
    displaced = _launch.empty(n_vertices, dtype=wp.vec3, device=device)
    wide = _launch.empty(n_vertices, dtype=wp.vec3d, device=device)
    diffused = _launch.empty(n_vertices, dtype=wp.vec3d, device=device)
    constraint = _VolumeConstraint(faces, device, anchors=iterations + int(pre_smooth))
    coeff = wp.float64(lamb)

    def relax(anchor: wp.array[wp.vec3]) -> None:
        # One ``filter_laplacian`` pass of ``wide`` (``anchor`` widened) into ``positions``: the
        # constraint anchored to it, one diffusion pass, rescaled and narrowed as it is written.
        constraint.anchor(wide, anchor)
        _diffuse_pass(operator, coeff, wide, diffused)
        constraint.apply(diffused, out=positions)

    # Without the pre-smoothing pass the first displacement reads the input itself.
    current = vertices
    if pre_smooth:
        od.array.copyto(wide, vertices)
        relax(vertices)
        current = positions
    for step in range(iterations):
        amount = pressure * (step + 1) / iterations if gradual else pressure
        _launch.launch(
            kernel_smoothing.inflate_displace,
            dim=n_vertices,
            inputs=[current, faces, vf_offsets, vf_indices, wp.float32(amount)],
            outputs=[displaced, wide],
            device=device,
        )
        relax(displaced)
        current = positions
    return positions

Pull needle-like vertices back onto the surface, leaving every other vertex untouched.

A spike is a vertex whose incident corner angles sum to less than min_angle_sum. On a flat surface that sum is 2 * pi; the sharper the cone, the smaller it gets, and a vertex on a thin needle -- the classic scan and reconstruction artifact -- has a sum near zero. Each pass replaces the flagged vertices by the average of their closed 1-rings and nothing else moves: this is not a smoothing filter restricted to a region, it is a repair that touches only the vertices that fail the test. Flattening a spike changes its neighbours' angle sums, so the pass repeats -- a needle whose base is itself spiky needs more than one -- and stops as soon as a pass finds none.

def filter_spikes(
    vertices: wp.array[wp.vec3],
    faces: wp.array[wp.int32],
    min_angle_sum: float,
    *,
    max_iter: int = 10,
    return_count: bool = False,
) -> wp.array[wp.vec3] | tuple[wp.array[wp.vec3], int]:
    """
    Pull needle-like vertices back onto the surface, leaving every other vertex untouched.

    A *spike* is a vertex whose incident corner angles sum to less than ``min_angle_sum``. On a
    flat surface that sum is ``2 * pi``; the sharper the cone, the smaller it gets, and a vertex on
    a thin needle -- the classic scan and reconstruction artifact -- has a sum near zero. So the
    threshold is read in radians against a full turn, and a value like ``0.5 * pi`` selects
    genuinely degenerate cones while leaving ordinary sharp features alone.

    Each pass replaces the flagged vertices by the average of their closed 1-rings and **nothing
    else moves**: this is not a smoothing filter restricted to a region, it is a repair that touches
    only the vertices that fail the test. Flattening a spike changes its neighbours' angle sums, so
    the pass repeats -- a needle whose base is itself spiky needs more than one -- and stops as soon
    as a pass finds none.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    min_angle_sum
        Angle-sum threshold in radians. A vertex is a spike when its incident angles sum below it.
        Compare against ``2 * pi``, the flat value.
    max_iter
        Cap on the number of passes.
    return_count
        If ``True``, also return ``flattened``.

    Returns
    -------
    vertices : wp.array[wp.vec3]
        ``(n_vertices,)`` repaired positions on ``vertices.device``. Connectivity is untouched, so
        ``faces`` stays valid.
    flattened : int, optional
        Present when ``return_count=True``. How many vertex moves were made, summed over the passes
        -- so a vertex fixed twice counts twice, which makes it a report rather than a count of
        anything in the output. Zero means nothing was flagged and the buffer is the input's. The
        pass loop stops itself as soon as a pass finds no spike, so the default return is a bare
        position buffer that drops into a filter chain like every other function here.

    Raises
    ------
    ValueError
        If ``max_iter`` is negative.
    RuntimeError
        If ``vertices`` and ``faces`` are not all on one device.

    See Also
    --------
    [`filter_neighborhood_average`][ordito.smoothing.filter_neighborhood_average]
        The unrestricted version of the move this makes, over every vertex.
    [`vertex_defects`][ordito.vertices.vertex_defects]
        ``2 * pi`` minus the same angle sum, which is what the threshold is read against.
    [`validation.face_defective_mask`][ordito.validation.face_defective_mask]
        Flags the *faces* a spike produces, where this flags the vertex itself.

    Examples
    --------
    A vertex of a sphere pulled out to three times the radius is a spike; it is moved to the
    average of its closed 1-ring, and no other vertex moves:

    ```python
    import math

    import warp as wp

    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=2)
    spiky = vertices.numpy()
    spiky[0] *= 3.0
    spiky = wp.array(spiky, dtype=wp.vec3)
    repaired, flattened = od.smoothing.filter_spikes(
        spiky, faces, 0.5 * math.pi, return_count=True
    )
    print(flattened)  # 1
    print(f"{float((repaired.numpy()[0] ** 2).sum() ** 0.5):.2f}")  # 1.30
    print((repaired.numpy()[1:] == spiky.numpy()[1:]).all())  # True
    ```
    """
    require_same_device(vertices=vertices, faces=faces)
    if max_iter < 0:
        raise ValueError(f"max_iter must be non-negative, got {max_iter}")
    device = faces.device
    n_vertices = vertices.size
    if n_vertices == 0 or faces.size == 0 or max_iter == 0:
        cloned = _launch.clone(vertices)
        return (cloned, 0) if return_count else cloned

    positions = _launch.clone(vertices)
    flattened = 0
    spikes = _launch.empty(n_vertices, dtype=wp.bool, device=device)
    # The uniform closed 1-ring average of a spike reads only its row of
    # ``laplacian.laplacian(symmetric=True)``. At ``equal_weight=True`` the operator reads no
    # positions -- every off-diagonal weight is ``1`` before the row normalization -- so it is the
    # mesh's *topology*, which no pass changes: built once, on the first pass that needs it, when
    # the spikes are many. When they are few, a pass instead sorts only the spike rows' neighbour
    # keys (``_flatten_few_spikes``), which costs a face pass rather than a whole-mesh operator.
    operator: odt.BsrMatrix[wp.float32] | None = None
    # A pass is three launches over buffers allocated here: the corner angles summed per vertex as
    # they are formed, the spikes marked and counted (re-zeroing the sums for the next pass), and
    # the spikes alone replaced by their closed 1-ring average -- one
    # ``filter_neighborhood_average`` pass and a select, with the same arithmetic, so the same
    # answer.
    angle_sums = _launch.zeros(n_vertices, dtype=wp.float32, device=device)
    # Two zeroed counters per pass, so no pass clears one: the spike count and the cursor of the
    # first neighbour-key collection ``_flatten_few_spikes`` runs.
    counts = _launch.zeros(2 * max_iter, dtype=wp.int32, device=device)
    nxt = _launch.empty(n_vertices, dtype=wp.vec3, device=device)
    n_faces = faces.size // 3
    # The spike test is ``angle_sum < min_angle_sum``, applied to the angle *defect*
    # ``2 * pi - angle_sum`` instead: ``defect > 2 * pi - min_angle_sum``, the quantity
    # ``vertices.vertex_defects`` returns.
    min_defect = wp.float32(2.0 * math.pi - min_angle_sum)
    for index in range(max_iter):
        _launch.launch(
            kernel_vertices.scatter_corner_angles,
            dim=n_faces,
            inputs=[positions, faces, angle_sums],
            device=device,
        )
        _launch.launch(
            kernel_smoothing.mark_spikes,
            dim=n_vertices,
            inputs=[angle_sums, min_defect, 2 * index, spikes, counts],
            device=device,
        )
        # One readback per pass, and it is the stopping test: whether any vertex is still a spike is
        # a device-side fact that a Python loop cannot branch on otherwise.
        n_spikes = int(read_scalar(counts, index=2 * index))
        if n_spikes == 0:
            break
        flattened += n_spikes
        if n_spikes * _FEW_SPIKES_RATIO <= n_vertices:
            _flatten_few_spikes(positions, faces, spikes, n_spikes, counts, 2 * index + 1)
            continue
        if operator is None:
            operator = laplacian.laplacian(vertices, faces, symmetric=True)
        _launch.launch(
            kernel_smoothing.flatten_spikes_pass,
            dim=n_vertices,
            inputs=[operator.offsets, operator.columns, operator.values, spikes, positions, nxt],
            device=device,
        )
        positions, nxt = nxt, positions
    return (positions, flattened) if return_count else positions

A plain 1-ring average moves every vertex toward the inside of the surface it curves around, so a closed shape loses volume with every pass. filter_laplacian's volume_constraint answers that by rescaling the whole mesh at the end, which restores the total and is wrong everywhere the shrinkage was not uniform. This answers it per vertex instead: the relax displacement is computed as a field, and each vertex then has its own neighbourhood's average displacement subtracted from its own.

That difference is the whole method. A translation shared by a neighbourhood -- which is what shrinkage locally is -- cancels exactly, while the high-frequency part of the displacement, which is the noise the relax was for, survives untouched. No global rescale, and a mesh with a flat region and a curved one is treated correctly in both.

    so a closed shape loses volume with every pass.
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]'s ``volume_constraint`` answers that
    by rescaling the whole mesh at the end, which restores the total and is wrong everywhere the
    shrinkage was not uniform. This answers it per vertex instead: the relax displacement is
    computed as a *field*, and each vertex then has its own neighbourhood's **average
    displacement** subtracted from its own.

    That difference is the whole method. A translation shared by a neighbourhood -- which is what
    shrinkage locally is -- cancels exactly, while the high-frequency part of the displacement,
    which is the noise the relax was for, survives untouched. No global rescale, and a mesh with a
    flat region and a curved one is treated correctly in both.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    iterations
        Number of passes. ``0`` returns a copy.
    force
        Fraction of the way to the 1-ring average each pass moves before the correction.
    region
        ``(n_vertices,)`` mask of the vertices allowed to move. ``None`` moves every one.
        A neighbour outside the region contributes its position to the average but no displacement
        to the correction, so a vertex on the region's edge is corrected by less than an interior
        one -- which is what stops the region from tearing away from the rest.
    max_displacement
        Clamp every vertex into a ball of this radius around its **input** position, applied after
        each pass. ``None`` leaves the relaxation unbounded.
    unique_edges
        ``(n_edges, 2)`` [`edges_unique`][ordito.edges.edges_unique] of ``faces``
        ([`Trimesh.edges_unique`][ordito.mesh.Trimesh.edges_unique]), the edges the neighbour
        rows are built from, to spare the edge sort. Trusted, not checked.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` relaxed positions on ``vertices.device``.

    Raises
    ------
    ValueError
        If ``iterations`` is negative, if ``max_displacement`` is negative, or if ``region`` is not
        a length-``n_vertices`` ``wp.bool`` array.

    [`equalize_triangle_areas`][ordito.smoothing.equalize_triangle_areas]

    Examples
    --------
    Smoothing a unit sphere whose radii were jittered by up to 3 % removes most of the jitter, and
    unlike a plain relaxation it keeps the volume:

    ```python
    import numpy as np
    import warp as wp

    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    noise = np.random.default_rng(0).uniform(0.97, 1.03, (vertices.shape[0], 1))
    noisy = wp.array(vertices.numpy() * noise, dtype=wp.vec3)

    ratio = od.measures.volume(smoothed, faces) / od.measures.volume(noisy, faces)
    print(abs(ratio - 1.0) < 0.01)  # True
    ```

    require_same_device(vertices=vertices, faces=faces, region=region, unique_edges=unique_edges)
    device = vertices.device
    n_vertices = vertices.size
    active, limit = _relaxation_state(vertices, iterations, region, max_displacement)
    if not active:
        return _launch.clone(vertices)

    # Sorted rows: the ring sums below run in row order, and sorted rows are exactly the CSR
    # structure a triplet build would give, with no sort of every edge twice.
    if unique_edges is None:
        unique_edges, _ = od.edges.edges_unique(faces, n_vertices=n_vertices, validate=False)
    columns, offsets = od.graph.edges_to_neighbor_lists(
        n_vertices, unique_edges, validate=False, sort_rows=True
    )
    push = _launch.empty(n_vertices, dtype=wp.vec3, device=device)

    def relax_pass(src: wp.array[wp.vec3], dst: wp.array[wp.vec3]) -> None:
        _launch.launch(
            kernel_smoothing.ring_push_forces,
            dim=n_vertices,
            inputs=[src, offsets, columns, region, wp.float32(force), push],
            device=device,
        )
        _launch.launch(
            kernel_smoothing.apply_push_keeping_volume,
            dim=n_vertices,
            inputs=[src, offsets, columns, region, push, vertices, limit, dst],
            device=device,
        )

    return _float32_passes(vertices, iterations, relax_pass)

    Move each vertex onto a surface fitted to its **neighbourhood**, rather than toward its 1-ring.

    Every diffusion filter here is a 1-ring operator, so the largest feature it can see is one edge
    across and its idea of "where the surface is" is the average of six neighbours. This fits a
    local surface -- a least-squares plane, or a quadric graph over that plane -- to every vertex

    fitted.

    genuinely curved surface if the radius is large. ``fit="quadric"`` keeps curvature, because a
    curved surface *is* in its model space, and is the one to use on anything but a plate.

    which is exactly the case that corrupts a fit. ``method="meshlib"`` takes the stricter ball of
    vertices reached along mesh edges within ``dilate_radius`` of path length, rebuilt from the

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    dilate_radius
        Radius of the neighbourhood ball, in world units. It has no scale-free default: below one
        edge length the ball is the vertex alone and the call is a no-op, and the useful range
        starts at a small multiple of the mean edge length
        ([`edges_unique_length`][ordito.edges.edges_unique_length]).
    iterations
        Number of passes. ``0`` returns a copy. Under ``method="geodesic_ball"`` the
        neighbourhoods are built **once**, from the input positions, and reused -- the ball's
        membership is a topological choice and rebuilding it per pass would cost more than the fit.
    force
        Fraction of the way to the fitted surface each pass moves.
    fit
        ``"planar"`` for a least-squares plane, ``"quadric"`` for a 6-coefficient quadric graph over
        it.
    region
        ``(n_vertices,)`` mask of the vertices allowed to move. ``None`` moves every one.
        Vertices outside it still populate their neighbours' balls.
    max_displacement
        Clamp every vertex into a ball of this radius around its **input** position, applied after
        each pass. ``None`` leaves the relaxation unbounded.
    method
        ``"geodesic_ball"`` for the edge-connected part of the Euclidean ball of ``dilate_radius``
        around each vertex, built once from the input. ``"meshlib"`` for every vertex whose
        shortest path along mesh edges is at most ``dilate_radius`` long (path lengths summed in
        ``float32``, the radius inclusive), rebuilt from each pass's starting positions, with the
        fit formed in ``float64``. A path is never shorter than the straight line, so this ball is
        the smaller of the two; walking it again every pass is what the option costs.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` relaxed positions on ``vertices.device``.

    Raises
    ------
    ValueError
        If ``iterations`` is negative, if ``dilate_radius`` is not positive, if
        ``max_displacement`` is negative, if ``fit`` or ``method`` is not one of its two
        names, or if ``region`` is not a length-``n_vertices`` ``wp.bool`` array.

        A plane fit needs three independent points and the quadric six, so a vertex whose ball holds

        returns the input -- check the result moved before concluding the parameters were right.

    ```python
    import numpy as np
    import warp as wp

    import ordito as od

    vertices, faces = od.creation.grid(count=(17, 17))
    noisy = vertices.numpy()

    noisy = wp.array(noisy, dtype=wp.vec3)

    print(along_edges.numpy()[:, 2].std() < 0.5 * noisy.numpy()[:, 2].std())  # True
    ```

    require_same_device(vertices=vertices, faces=faces, region=region)
    if fit not in ("planar", "quadric"):
        raise ValueError(f"fit must be 'planar' or 'quadric', got {fit!r}")
    if method not in ("geodesic_ball", "meshlib"):
        raise ValueError(f"method must be 'geodesic_ball' or 'meshlib', got {method!r}")
    if dilate_radius <= 0.0:
        raise ValueError(f"dilate_radius must be positive, got {dilate_radius}")
    device = vertices.device
    n_vertices = vertices.size
    active, limit = _relaxation_state(vertices, iterations, region, max_displacement)
    if not active:
        return _launch.clone(vertices)

    # Which vertices are in the ball is a decision about the surface's connectivity, made from the
    # input positions on every pass: the relaxation moves everything by less than the radius anyway.
    # ``min_count=1`` disables the nearest-neighbour backfill: a ball too small to fit is a
    # documented no-op here, and backfilling would quietly fit something else instead.
    #
    # The fit is a per-vertex reduction over the ball, so it reads each chunk of the walk's queue
    # rows as the walk leaves them and the neighbour lists are never packed: a list that can reach
    # ``PER_SOURCE_MAX_NEIGHBORS`` entries a vertex outgrows the device on a large scan at a radius
    # of a few percent of its size. Several passes over a mesh whose packed list is bounded small
    # build it once and reuse it, since a walk per pass costs more than a fit.
    def relax_launch(
        src: wp.array[wp.vec3],
        dst: wp.array[wp.vec3],
        neighbor_indices: wp.array[wp.int32],
        neighbor_offsets: wp.array[wp.int32],
        row_stride: wp.int32,
        start: int,
        dim: int,
    ) -> None:
        _launch.launch(
            kernel_smoothing.relax_approx_step_d
            if method == "meshlib"
            else kernel_smoothing.relax_approx_step,
            dim=dim,
            inputs=[
                src,
                neighbor_indices,
                neighbor_offsets,
                row_stride,
                wp.int32(start),
                region,
                vertices,
                wp.float32(force),
                fit == "quadric",
                limit,
                dst,
            ],
            device=device,
        )

    if method == "meshlib":
        # Each pass walks its balls over the positions it starts from, so the ball follows the
        # surface as it moves; a fit reads each chunk's rows as the walk leaves them.
        path_walk = od.neighbors._EdgePathBallWalk(  # pyright: ignore[reportPrivateUsage]
            faces, n_vertices, dilate_radius
        )

        def relax_pass(src: wp.array[wp.vec3], dst: wp.array[wp.vec3]) -> None:
            for start, m in path_walk.chunks(src):
                relax_launch(
                    src, dst, path_walk.rows_flat, path_walk.counts, path_walk.row_stride, start, m
                )
            path_walk.warn_clipped()

    elif iterations > 1 and n_vertices <= _PACKED_BALL_MAX_VERTICES:
        neighbor_indices, neighbor_offsets, _ = od.neighbors.geodesic_ball(
            vertices, faces, dilate_radius, min_count=1
        )

        def relax_pass(src: wp.array[wp.vec3], dst: wp.array[wp.vec3]) -> None:
            relax_launch(src, dst, neighbor_indices, neighbor_offsets, wp.int32(0), 0, n_vertices)

    else:
        walk = od.neighbors._GeodesicBallWalk(  # pyright: ignore[reportPrivateUsage]
            vertices, faces, dilate_radius, 1
        )

        def relax_pass(src: wp.array[wp.vec3], dst: wp.array[wp.vec3]) -> None:
            for start, m in walk.chunks():
                relax_launch(src, dst, walk.rows_flat, walk.counts, walk.row_stride, start, m)
            walk.warn_clipped()

    return _float32_passes(vertices, iterations, relax_pass)

Notes

recompute is a different filter, not a tuning of this one: pytorch3d.ops.taubin_smoothing rebuilds its inverse-distance operator from the current geometry before each half-pass, and matching that convention is what makes recompute=True agree with it, where the fixed operator does not. The default is unchanged and stays the fixed operator, which is trimesh's filter and this group's oracle.

It is pinned to the inverse-distance weighting rather than taking a weighting of its own, and that is not a simplification: the uniform operator is 1 / degree off the diagonal, a function of the connectivity alone, which a position filter never changes -- so recomputing it would rebuild the identical matrix every pass and cost without doing anything. Only the geometry-dependent branch has anything to recompute.

recompute reassembles a sparse operator every pass instead of once, which is more expensive; the connectivity never changes, though, so every pass shares one mesh_operator_pattern and only rewrites the weights.

def filter_taubin(
    vertices: wp.array[wp.vec3],
    faces: wp.array[wp.int32],
    lamb: float = 0.5,
    nu: float = 0.5,
    iterations: int = 10,
    laplacian_operator: odt.BsrMatrix[wp.float32] | None = None,
    *,
    recompute: bool = False,
) -> wp.array[wp.vec3]:
    """
    Taubin lambda/nu mesh smoothing (Vollmer et al.).

    Alternates a shrinking diffusion step (``+lamb``) on even passes with an inflating step
    (``-nu``) on odd passes, so the low-frequency shape is preserved while high-frequency noise is
    removed with little volume loss. Mirrors [`trimesh.smoothing.filter_taubin`][].

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    lamb
        Shrinking step size in ``[0, 1]``.
    nu
        Inflating step size in ``[0, 1]``; typically chosen so ``0 < 1/lamb - 1/nu < 0.1``.
    iterations
        Number of smoothing passes (shrink and inflate alternate by pass index).
    laplacian_operator
        ``(n_vertices, n_vertices)`` optional precomputed row-stochastic operator (see
        [`laplacian`][ordito.laplacian.laplacian]). Autogenerated (uniform weights) when ``None``.
        Passing one *and* setting ``recompute`` is a contradiction and raises.
    recompute
        Reassemble the inverse-distance operator from the *current* positions before every pass,
        instead of applying one operator throughout. Off by default; see the ``Notes`` — it is a
        different filter and markedly more expensive per pass.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` smoothed vertex positions on ``vertices.device``.

    Raises
    ------
    ValueError
        If ``recompute`` is set together with ``laplacian_operator``, which would be ignored.
    RuntimeError
        If ``vertices`` and ``faces`` are not all on one device.

    See Also
    --------
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]
    [`trimesh.smoothing.filter_taubin`][]
    [`laplacian`][ordito.laplacian.laplacian]
        The operator this applies, and the ``equal_weight`` switch ``recompute`` pins to ``False``.

    Notes
    -----
    ``recompute`` is a different filter, not a tuning of this one:
    ``pytorch3d.ops.taubin_smoothing`` rebuilds its inverse-distance operator from the current
    geometry before each half-pass, and matching that convention is what makes ``recompute=True``
    agree with it, where the fixed operator does not. The default is unchanged and stays the fixed
    operator, which is trimesh's filter and this group's oracle.

    It is pinned to the **inverse-distance** weighting rather than taking a weighting of its own,
    and that is not a simplification: the uniform operator is ``1 / degree`` off the diagonal, a
    function of the connectivity alone, which a position filter never changes -- so recomputing it
    would rebuild the identical matrix every pass and cost without doing anything. Only the
    geometry-dependent branch has anything to recompute.

    ``recompute`` reassembles a sparse operator every pass instead of once, which is more
    expensive; the connectivity never changes, though, so every pass shares one
    [`mesh_operator_pattern`][ordito.laplacian.mesh_operator_pattern] and only rewrites the
    weights.

    Examples
    --------
    Alternating a shrinking and an inflating step loses far less volume than plain Laplacian
    smoothing:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    volume = od.measures.volume(vertices, faces)
    taubin = od.smoothing.filter_taubin(vertices, faces)
    laplacian = od.smoothing.filter_laplacian(vertices, faces, volume_constraint=False)
    print(od.measures.volume(taubin, faces) > od.measures.volume(laplacian, faces))  # True
    print(abs(od.measures.volume(taubin, faces) / volume - 1) < 0.01)  # True
    ```
    """
    require_same_device(vertices=vertices, faces=faces)
    if recompute and laplacian_operator is not None:
        raise ValueError("recompute rebuilds the operator each pass; do not also pass one")
    n = vertices.size
    if n == 0 or iterations == 0:
        return _launch.clone(vertices)

    operator = None if recompute else _resolved_operator(vertices, faces, laplacian_operator)
    # The recompute path reassembles the operator every pass from *moved* positions, but over
    # connectivity that never changes -- so its sparsity is built once here and every pass only
    # writes the weights.
    pattern = (
        laplacian.mesh_operator_pattern(faces, n, operator="laplacian_symmetric")
        if recompute and faces.size > 0
        else None
    )

    def taubin_pass(index: int, src: _Positions, dst: _Positions) -> None:
        # ``filter_laplacian``'s explicit pass, with the step alternating sign.
        pass_operator = (
            laplacian.laplacian(
                vertices if index == 0 else _as_vec3(cast("wp.array[wp.vec3d]", src)),
                faces,
                equal_weight=False,
                pattern=pattern,
            )
            if operator is None
            else operator
        )
        coeff = lamb if index % 2 == 0 else -nu
        _diffuse_pass(pass_operator, wp.float64(coeff), src, dst)

    return _vec3_passes(vertices, iterations, taubin_pass)

def filter_mut_dif_laplacian(
    vertices: wp.array[wp.vec3],
    faces: wp.array[wp.int32],
    lamb: float = 0.5,
    iterations: int = 10,
    volume_constraint: bool = True,
    laplacian_operator: odt.BsrMatrix[wp.float32] | None = None,
    *,
    face_normals: wp.array[wp.vec3] | None = None,
    face_areas: wp.array[wp.float32] | None = None,
) -> wp.array[wp.vec3]:
    """
    Laplacian smoothing with a mutable diffusion coefficient (Barroqueiro et al.).

    Each pass runs a Laplacian diffusion step whose speed is adapted **per vertex**: the
    coefficient ``lamber`` is scaled by how much of the vertex's Laplacian residual lies along
    its normal, so flat regions diffuse quickly while feature regions diffuse slowly. When
    ``volume_constraint`` is set, the mesh is inflated along its vertex normals (rather than
    isotropically rescaled) to counteract shrinkage. Mirrors
    [`trimesh.smoothing.filter_mut_dif_laplacian`][] but returns a new vertex array instead of
    mutating the mesh in place.

    Following the reference, the vertex normals (and the finite-difference step ``eps``) are
    computed once from the input mesh and held constant across all passes.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    lamb
        Diffusion speed. ``0`` leaves the mesh unchanged; larger values smooth faster.
    iterations
        Number of smoothing passes.
    volume_constraint
        If ``True`` inflate the mesh along its vertex normals after each pass to preserve its
        initial volume (meaningful only for watertight meshes).
    laplacian_operator
        ``(n_vertices, n_vertices)`` optional precomputed row-stochastic operator (see
        [`laplacian`][ordito.laplacian.laplacian]). Autogenerated (uniform weights) when ``None``.
    face_normals
        ``(n_faces,)`` optional unit face normals and matching areas from
        [`face_normals_and_areas`][ordito.triangles.face_normals_and_areas]; recomputed together
        when either is ``None``. [`Trimesh.face_normals`][ordito.mesh.Trimesh.face_normals] and
        [`Trimesh.face_areas`][ordito.mesh.Trimesh.face_areas] cache the pair.
    face_areas
        ``(n_faces,)`` face areas; see ``face_normals``.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` smoothed vertex positions on ``vertices.device``.

    Raises
    ------
    RuntimeError
        If ``vertices``, ``faces``, ``face_normals`` and ``face_areas`` are not all on one device.

    Warns
    -----
    UserWarning
        When the result is sensitive to rounding-level changes of the input (see Notes).

    Notes
    -----
    Every step divides by the mean of ``1 / |N . (V - L.V)|`` over the vertices. Where a vertex's
    normal residual is near zero -- a saddle, a bump's inflection -- that term dominates the mean
    and its value is set by rounding, so the whole result is chaotically sensitive to its input: a
    1e-7 relative change of the vertices can move it by a percent of the mesh's extent, in the
    reference implementation as here. The call measures the mean's relative uncertainty under the
    input's ``float32`` rounding on every pass and warns when it exceeds 1e-3. On a convex or
    otherwise saddle-free surface it stays near 1e-5.

    See Also
    --------
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]
    [`filter_humphrey`][ordito.smoothing.filter_humphrey]
    [`filter_taubin`][ordito.smoothing.filter_taubin]
    [`trimesh.smoothing.filter_mut_dif_laplacian`][]

    Examples
    --------
    The volume constraint inflates along the vertex normals after each pass, so a sphere keeps its
    volume instead of shrinking:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    volume = od.measures.volume(vertices, faces)
    kept = od.smoothing.filter_mut_dif_laplacian(vertices, faces)
    print(f"{od.measures.volume(kept, faces) / volume:.3f}")  # 1.000
    shrunk = od.smoothing.filter_mut_dif_laplacian(vertices, faces, volume_constraint=False)
    print(od.measures.volume(shrunk, faces) < volume)  # True
    ```
    """
    require_same_device(
        vertices=vertices, faces=faces, face_normals=face_normals, face_areas=face_areas
    )
    device = vertices.device
    n = vertices.size
    if n == 0 or iterations == 0:
        return _launch.clone(vertices)

    operator = _resolved_operator(vertices, faces, laplacian_operator)
    # The ``float64`` iterate. With no volume constraint the first pass reads the ``float32`` input
    # itself, widened as it is read, and the last writes the ``float32`` answer; the constraint
    # sums the input's own volume in ``float64``, so it starts from a widened copy, and its last
    # correction writes the answer.
    positions: _Positions = _as_vec3d(vertices) if volume_constraint else vertices

    # Vertex normals and eps are computed once from the input mesh and reused every pass, matching
    # the trimesh reference (which reads normals off the un-mutated mesh inside its loop).
    if face_normals is None or face_areas is None:
        # ``mean_vertex_normals`` of the derived face normals, which the scatter forms in its own
        # thread, so no normal table is written; the areas only for the constraint's probe step.
        normal_sums = _launch.zeros((n, 3), dtype=wp.float64, device=device)
        n_faces = faces.size // 3
        _launch.launch(
            kernel_vertices.SCATTER_UNIT_NORMALS[wp.float64],
            dim=n_faces,
            inputs=[vertices, faces, normal_sums],
            device=device,
        )
        normals = _launch.empty(n, dtype=wp.vec3, device=device)
        _launch.launch(
            kernel_vertices.NORMALIZE_ACCUMULATED_ROWS[wp.float64],
            dim=n,
            inputs=[normal_sums, normals],
            device=device,
        )
        face_areas = None
        if volume_constraint:
            face_areas = _launch.empty(n_faces, dtype=wp.float32, device=device)
            _launch.launch(
                kernel_triangles.face_areas,
                dim=n_faces,
                inputs=[vertices, faces, face_areas],
                device=device,
            )
    else:
        normals = mean_vertex_normals(n, faces, face_normals)

    lv = _launch.empty(n, dtype=wp.vec3d, device=device)
    sensitivity = _launch.zeros(1, dtype=wp.float64, device=device)
    out = _launch.empty(n, dtype=wp.vec3, device=device)
    # The other ``float64`` iterate of the ping-pong, allocated by the first pass that writes it.
    nxt: wp.array[wp.vec3d] | None = None
    # The three volumes the constraint needs, kept on the device for the whole loop: the input's
    # (fixed), this pass's, and the eps-probe's, with the calibrated slope beside them. Reading any
    # of them back cost a full pipeline drain per smoothing pass -- and the pass count is the whole
    # point of this loop -- for arithmetic the two kernels below do themselves.
    #
    # All three are summed by ``wp.utils.array_sum``, deliberately the *same* reduction rather than
    # ``measures.volume``'s tiled one: the correction is ``slope * (vol_ini - vol)``, a difference
    # of two nearly equal volumes, so mixing two summation orders would show up there magnified
    # rather than in the last bits.
    constraint = None
    area_max = None
    if volume_constraint:
        # The largest face area, which sets the probe step ``0.01 * sqrt(max area)`` in the two
        # kernels that use it; areas are non-negative, so a zero seed is the maximum's identity.
        area_max = _launch.zeros(1, dtype=wp.float32, device=device)
        assert face_areas is not None
        if face_areas.size > 0:
            _launch.launch_tiled(
                kernel_reduce.MAX1D_TILED[wp.float32],
                dim=[kernel_reduce.blocks_1d(face_areas.size)],
                inputs=[face_areas, area_max],
                block_dim=TILE_1D,
                device=device,
            )
        probe = _launch.empty(n, dtype=wp.vec3d, device=device)
        scratch = _VolumeScratch.for_faces(faces, device)
        vol_ini, vol_probe, slope = (
            _launch.zeros(1, dtype=wp.float64, device=device) for _ in range(3)
        )
        scratch.accumulate(cast("wp.array[wp.vec3d]", positions), faces, vol_ini)
        constraint = (probe, scratch, vol_ini, vol_probe, slope)
    inv_n = wp.float64(1.0 / n)
    rows_per_block = kernel_smoothing.MUT_DIF_ROWS_PER_BLOCK
    n_blocks = (n + rows_per_block - 1) // rows_per_block
    # One ``(coefficients, sensitivity)`` row per block, rewritten by every pass and added in a
    # fixed order into the first two slots, so no pass clears it. With determinism off
    # (``ordito.config``) the commit is two slots the blocks add into by atomics, so each pass
    # takes its own pair of one buffer zeroed once, and no pass clears one.
    adil_slots = None
    if is_deterministic():
        adil_sum, _ = _launch.block_partials(n_blocks, 2, wp.float64, device)
    else:
        adil_slots = _launch.zeros(2 * iterations, dtype=wp.float64, device=device)
        adil_sum = adil_slots
    for index in range(iterations):
        if adil_slots is not None:
            adil_sum = _launch.view(adil_slots, 2 * index, 2 * index + 2)
        # The mean diffusion coefficient is summed on device by the pass that applies the operator
        # and consumed by the step kernel directly, so the loop body issues no host synchronisation.
        _launch.launch_tiled(
            kernel_smoothing.MUT_DIF_ADIL_PASS[positions.dtype],
            dim=[n_blocks],
            inputs=[operator.offsets, operator.columns, operator.values, positions, normals, 2],
            outputs=[lv, adil_sum],
            block_dim=TILE_1D,
            device=device,
        )
        # The volume constraint's first pass also writes the eps probe its slope calibrates on.
        probe = constraint[0] if constraint is not None and index == 0 else None
        last = index == iterations - 1
        if nxt is None and (constraint is not None or not last):
            nxt = _launch.empty(n, dtype=wp.vec3d, device=device)
        dst: _Positions = out if constraint is None and last else cast("wp.array[wp.vec3d]", nxt)
        _launch.launch(
            kernel_smoothing.MUT_DIF_STEP_SCALED[positions.dtype, dst.dtype],
            dim=n,
            inputs=[positions, lv, adil_sum, inv_n, wp.float64(lamb), normals, area_max],
            outputs=[dst, probe, sensitivity],
            device=device,
        )
        # The input is never written: a pass reading it hands the next one a fresh buffer.
        nxt = cast("wp.array[wp.vec3d]", positions) if positions.dtype == wp.vec3d else None
        positions = dst
        if constraint is not None:
            # Under the constraint every pass writes the ``float64`` ping-pong buffer.
            iterate = cast("wp.array[wp.vec3d]", dst)
            probe, scratch, vol_ini, vol_probe, slope = constraint
            vol_cur = scratch.volume
            scratch.accumulate(iterate, faces)
            if index == 0:
                scratch.accumulate(probe, faces, vol_probe)
            _launch.launch(
                kernel_smoothing.mut_dif_volume_correct,
                dim=n,
                inputs=[
                    normals,
                    vol_ini,
                    vol_cur,
                    vol_probe,
                    area_max,
                    wp.int32(1 if index == 0 else 0),
                    slope,
                ],
                outputs=[iterate, out if last else None],
                device=device,
            )

    # Host readback: the one number the warning decides on, read once after every pass is queued.
    uncertainty = float(read_scalar(sensitivity))
    if uncertainty > _MUT_DIF_SENSITIVITY_LIMIT:
        warnings.warn(
            "filter_mut_dif_laplacian: the mean diffusion coefficient every step divides by is "
            f"uncertain to {uncertainty:.2g} of itself from the input's float32 rounding alone: "
            "near-zero normal residuals (saddles, inflections) dominate it, so the result is "
            "sensitive to rounding-level changes of the input; see Notes.",
            stacklevel=2,
        )
    return out

Implicit fairing with the cotangent Laplace-Beltrami operator (Desbrun et al.).

Solves the backward-Euler diffusion (M - lamb L) V' = M V each pass, where L is the cotangent stiffness matrix (cotmatrix) and M the barycentric lumped mass matrix (mass_matrix). By default both are recomputed from the current geometry every pass, which is mean-curvature flow; with conformalized the stiffness stays the input's and only the mass follows the surface, which is the conformalized mean-curvature flow of Kazhdan, Solomon and Ben-Chen (2012; libigl tutorial 205). A single pass is the same either way. The solve uses float64 throughout.

Mean-curvature flow develops singularities: thin parts (a neck, an ear, a tube) shrink fastest and pinch off in finite time, whatever the time step. As they do, their triangles degenerate, the cotangent weights rebuilt from them grow without bound (a zero-area triangle contributes none), the system's conditioning collapses -- each pass's solve takes orders of magnitude more iterations -- and positions on the collapsing region stop meaning anything. That is the flow, not the solver. The conformalized flow keeps the input's weights, so its system stays about as well conditioned as the first pass's and a thin part thins without pinching off; it still shrinks the surface (toward a point on a closed mesh, toward the pinned rim on an open one), so a long enough flow still flattens triangles. Its reference geometry is each call's input: continue a conformalized flow by asking for more iterations, since a second call restarts it from the first call's output and a sequence of single-pass calls is the ordinary flow.

On a mesh with an open boundary the flow needs a boundary condition, which is what pin_boundary supplies: without one the unconstrained boundary is pulled inward, collapsing the triangles there, and further passes diverge rather than degrade gracefully. Pinning turns the pass into a Dirichlet problem over the interior, which is the formulation Desbrun et al. give for a surface with boundary.

A closed mesh has no boundary, so pin_boundary costs nothing and changes nothing there -- the solve is over every vertex either way, and curvature flow on a closed surface still shrinks it (a sphere contracts toward a point, which is the method working, not failing).

    See Also
    --------
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]
    [`cotmatrix`][ordito.laplacian.cotmatrix]
    [`mass_matrix`][ordito.laplacian.mass_matrix]

    Examples
    --------
    Mean-curvature flow contracts a closed surface, and keeps the pinned rim of an open one in
    place:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=2)
    faired = od.smoothing.filter_implicit_fairing(vertices, faces, iterations=5)
    print(od.measures.volume(faired, faces) < od.measures.volume(vertices, faces))  # True

    cap_vertices, cap_faces = od.creation.sphere_cap(subdivisions=2)
    faired_cap = od.smoothing.filter_implicit_fairing(cap_vertices, cap_faces, iterations=5)
    rim = od.boundary.boundary_vertex_indices(cap_vertices, cap_faces).numpy()
    print((faired_cap.numpy()[rim] == cap_vertices.numpy()[rim]).all())  # True
    ```
    """
    require_same_device(vertices=vertices, faces=faces)
    device = vertices.device
    n = vertices.size
    n_faces = faces.size // 3
    if n == 0 or n_faces == 0 or iterations == 0:
        return _launch.clone(vertices)

    positions = _as_vec3d(vertices)

    # Boundary topology is fixed for the whole flow, so the partition is built once. ``None`` means
    # "solve over every vertex" -- either the caller asked for the unconstrained flow, or the mesh
    # is closed and there is nothing to pin.
    dirichlet = _dirichlet_state(faces, n, device) if pin_boundary else None
    if dirichlet is not None and dirichlet.n_free == 0:
        # Every vertex is pinned, so the flow has no unknown to move and the pass is the identity.
        return _as_vec3(positions)

    # The sparsity depends on the connectivity alone, so it is built once for every pass.
    pattern = laplacian.mesh_operator_pattern(faces, n)
    # The conformalized flow keeps the input's stiffness for every pass; only the mass follows the
    # surface. The ordinary flow's stiffness is never stored: each pass forms its rows from the
    # half-cotangents inside the system kernel.
    fixed_stiffness = (
        laplacian.cotmatrix(vertices, faces, dtype=wp.float64, pattern=pattern).values
        if conformalized
        else _launch.empty(0, dtype=wp.float64, device=device)
    )
    # Per-face scratch every pass rewrites: the half-cotangents (unread by the conformalized flow)
    # and the exact area sums, which each face pass adds into from zero (the row pass clears every
    # entry it reads).
    cot_entries = odt.empty_2d((0 if conformalized else n_faces, 3), wp.float32, device=device)
    area_sums = _launch.zeros(n, dtype=wp.float64, device=device)
    # The ordinary flow's conditioning changes as the surface moves, so its solver decides again
    # after every iterated pass; the conformalized flow's stiffness is the input's, so its first
    # pass speaks for every later one.
    fairing = _FairingSolver(vertices, dirichlet, redecide=not conformalized)
    # Each pass's system values are a new buffer (the solver's state for one pass's operator must
    # not see the next one's), over a pattern fixed for the whole flow: the mesh pattern, or for the
    # Dirichlet pass its interior block, extracted once from it (the values that extraction reads
    # and writes are the first pass's buffer, which that pass then overwrites).
    first_values = _launch.empty(pattern.columns.size, dtype=wp.float64, device=device)
    template = od.array.bsr_from_csr(n, n, pattern.offsets, pattern.columns, first_values)
    if dirichlet is None:
        fixed_mask = free_map = None
        n_rows = n
        solution_2d = _component_columns(n, device)
    else:
        template, _ = twl.assemble_interior_system(
            template,
            dirichlet.fixed_mask,
            dirichlet.free_map,
            odt.empty_2d((0, n), wp.float64, device=device),
            dirichlet.n_free,
        )
        first_values = template.values
        fixed_mask, free_map = dirichlet.fixed_mask, dirichlet.free_map
        n_rows = dirichlet.n_free
        solution_2d = dirichlet.solution
    rhs = _component_columns(n_rows, device)
    # Viewed once: the solution buffer is never rebound.
    solution_rows = [odt.as_dense(solution_2d[column]) for column in range(3)]
    # The first pass reads the input itself: ``positions`` is its exact widening. Every pass then
    # writes the next one's ``wp.vec3`` positions beside its ``wp.vec3d`` ones, and the last pass's
    # are the answer. Two buffers alternate as those positions: a pass reads the last pass's and
    # writes the other.
    current = vertices
    narrowed: list[wp.array[wp.vec3]] = []
    for index in range(iterations):
        # Two launches assemble a pass: the face pass (half-cotangents of ``current`` -- the
        # ordinary flow re-linearises on the moving surface -- and the exact area sums), then one
        # row pass forming ``M - lamb L`` (or its interior block), the right-hand side and the CG
        # seed.
        _launch.launch(
            kernel_laplacian.cotmatrix_entries_and_area_sums,
            dim=n_faces,
            inputs=[current, faces, wp.int32(not conformalized)],
            outputs=[cot_entries, area_sums],
            device=device,
        )
        if first_values is not None:
            values, first_values = first_values, None
        else:
            values = _launch.empty_like(template.values)
        _launch.launch(
            kernel_smoothing.fairing_system_rows,
            dim=n,
            inputs=[
                pattern.offsets,
                pattern.columns,
                pattern.run_start,
                pattern.keys,
                wp.int32(pattern.n_keys),
                pattern.order,
                cot_entries,
                fixed_stiffness,
                area_sums,
                wp.float64(-float(lamb)),
                fixed_mask,
                free_map,
                positions,
                template.offsets,
            ],
            outputs=[values, rhs, solution_2d],
            device=device,
        )
        system = od.array.bsr_with_values(template, values)
        # One batched solve advances all three columns together; ``M - lamb L`` over the whole mesh
        # (or its interior block) is a solve long enough for the polynomial preconditioner.
        fairing.solve(system, rhs, solution_2d, maxiter=10 * n_rows)
        if index < 2:
            narrowed.append(_launch.empty(n, dtype=wp.vec3, device=device))
        current = narrowed[index % 2]
        if dirichlet is None:
            _launch.map(
                kernel_smoothing.combine_components_narrowed,
                solution_rows[0],
                solution_rows[1],
                solution_rows[2],
                out=[positions, current],
            )
        else:
            _launch.launch(
                kernel_smoothing.scatter_free_positions,
                dim=n,
                inputs=[
                    dirichlet.fixed_mask,
                    dirichlet.free_map,
                    solution_rows[0],
                    solution_rows[1],
                    solution_rows[2],
                    positions,
                    current,
                ],
                device=device,
            )

    return current

    # right-hand side every pass from the current cotangents (``band_dirichlet_values``). Keeping

    # loop every pass after the first replays; its Jacobi diagonal is the first pass's, which moves
    # the rate by a little and the answer not at all. Each pass warm-starts from the previous pass's
    # field.
    ring = [fixed_mask, free_map, offsets, vf_indices, faces]
    pattern_offsets, columns = _band_pattern(
        faces, (vf_indices, offsets), fixed_mask, free_map, n_free
    )
    nnz = columns.size
    system = _csr_matrix(
        n_free, pattern_offsets, columns, _launch.empty(nnz, dtype=wp.float64, device=device)
    )
    rhs = odt.as_array2d(_launch.empty((1, n_free), dtype=wp.float64, device=device), wp.float64)
    solution = odt.as_array2d(
        _launch.zeros((1, n_free), dtype=wp.float64, device=device), wp.float64
    )

    def boundary_pass(src: wp.array[wp.vec3], dst: wp.array[wp.vec3]) -> None:
        _launch.launch(
            kernel_smoothing.band_dirichlet_values,
            dim=n_vertices,
            inputs=[*ring, src, field_2d, pattern_offsets, columns],
            outputs=[system.values, rhs],
            device=device,
        )
        twl.solve_spd_columns(system, rhs, solution, tol=twl.CG_TOLERANCE)
        # The projection reads the field as the pinned values plus the solve's answer, in place.
        _launch.launch(
            kernel_smoothing.project_to_zero_isoline,
            dim=n_vertices,
            inputs=[
                src,
                faces,
                offsets,
                vf_indices,
                field[0],
                free,
                free_map,
                solution[0],
                _ISOLINE_DAMPING,
            ],
            outputs=[dst],
            device=device,
        )

    return _float32_passes(vertices, iterations, boundary_pass)

Sharpen a surface by adding back the detail a smoothing pass removes.

The inverse of a smoothing filter, built from one: the difference between the mesh and its Laplacian-smoothed self is its high-frequency content, so adding a multiple of that difference exaggerates every feature. This is unsharp masking, the photographic technique, applied to vertex positions instead of pixels — MeshLab spells it apply_coord_unsharp_mask — and it is the standard way to recover crispness lost to an earlier smoothing or a decimation. With the default operator it is MeshLab's filter: each smoothing pass weights a neighbour by the faces on its edge and keeps a rim vertex on the rim (face_weighted_laplacian).

method="graph_laplacian" is the other common sharpener, Open3D's filter_sharpen: each pass pushes every vertex away from its undirected 1-ring by weight times the unnormalized graph Laplacian, v + weight * sum_j (v - v_j), so a high-degree vertex moves further. It subtracts no smoothed copy, and iterations repeats the step rather than deepening a smoothing.

The name says what it returns, which is positions rather than a mask: the *_mask family in this package is boolean throughout.

def filter_sharpen(
    vertices: wp.array[wp.vec3],
    faces: wp.array[wp.int32],
    *,
    weight: float = 0.3,
    weight_original: float = 1.0,
    iterations: int = 5,
    laplacian_operator: odt.BsrMatrix[wp.float32] | None = None,
    method: Literal["unsharp_mask", "graph_laplacian"] = "unsharp_mask",
) -> wp.array[wp.vec3]:
    """
    Sharpen a surface by adding back the detail a smoothing pass removes.

    The inverse of a smoothing filter, built from one: the difference between the mesh and its
    Laplacian-smoothed self *is* its high-frequency content, so adding a multiple of that difference
    exaggerates every feature. This is **unsharp masking**, the photographic technique, applied to
    vertex positions instead of pixels — MeshLab spells it ``apply_coord_unsharp_mask`` — and it is
    the standard way to recover crispness lost to an earlier smoothing or a decimation. With the
    default operator it is MeshLab's filter: each smoothing pass weights a neighbour by the faces on
    its edge and keeps a rim vertex on the rim
    ([`face_weighted_laplacian`][ordito.laplacian.face_weighted_laplacian]).

    ``method="graph_laplacian"`` is the other common sharpener, Open3D's ``filter_sharpen``: each
    pass pushes every vertex away from its undirected 1-ring by ``weight`` times the *unnormalized*
    graph Laplacian, ``v + weight * sum_j (v - v_j)``, so a high-degree vertex moves further. It
    subtracts no smoothed copy, and ``iterations`` repeats the step rather than deepening a
    smoothing.

    The name says what it returns, which is *positions* rather than a mask: the ``*_mask`` family
    in this package is boolean throughout.

    Parameters
    ----------
    vertices
        ``(n_vertices,)`` mesh vertex positions. Not modified.
    faces
        ``(3 * n_faces,)`` triangle index buffer.
    weight
        How much of the detail to add back. ``0`` leaves the mesh unchanged and large values amplify
        noise as readily as features. MeshLab's ``weight``, default ``0.3``; Open3D's ``strength``
        under ``method="graph_laplacian"``.
    weight_original
        Multiplier on the original position, MeshLab's ``weightorig``. ``1`` (the default) keeps the
        surface where it is and only sharpens; anything else scales the whole mesh about the origin.
        The unsharp mask's alone: ``method="graph_laplacian"`` has no original-position term.
    iterations
        Laplacian passes used to define "smoothed", so this sets the *scale* of detail that gets
        amplified: more passes remove lower frequencies and therefore sharpen more coarsely.
        MeshLab's ``iterations``, default ``5``. Under ``method="graph_laplacian"``, the number of
        sharpening steps, Open3D's ``number_of_iterations``.
    laplacian_operator
        ``(n_vertices, n_vertices)`` optional precomputed operator: the row-stochastic smoothing
        operator (MeshLab's, [`face_weighted_laplacian`][ordito.laplacian.face_weighted_laplacian],
        built here when ``None``), or under ``method="graph_laplacian"`` the graph Laplacian to
        step through ([`graph_laplacian`][ordito.laplacian.graph_laplacian], built here when
        ``None``).
    method
        ``"unsharp_mask"`` (default) or ``"graph_laplacian"``, the two sharpeners above.

    Returns
    -------
    wp.array[wp.vec3]
        ``(n_vertices,)`` sharpened vertex positions on ``vertices.device``.

    Raises
    ------
    RuntimeError
        If ``vertices`` and ``faces`` are not all on one device.
    ValueError
        If ``method`` is not ``"unsharp_mask"`` or ``"graph_laplacian"``, or is
        ``"graph_laplacian"`` with a ``weight_original`` other than ``1``.

    See Also
    --------
    [`filter_laplacian`][ordito.smoothing.filter_laplacian]
    [`filter_two_step`][ordito.smoothing.filter_two_step]
    [`ordito.laplacian.face_weighted_laplacian`][]
        The unsharp mask's default smoothing operator.

    Examples
    --------
    Sharpening exaggerates what smoothing removes; on a sphere that is its curvature, so the
    sphere grows:

    ```python
    import ordito as od

    vertices, faces = od.creation.icosphere(subdivisions=3)
    sharpened = od.smoothing.filter_sharpen(vertices, faces)
    print(od.measures.volume(sharpened, faces) > od.measures.volume(vertices, faces))  # True
    ```
    """
    require_same_device(vertices=vertices, faces=faces)
    if method not in ("unsharp_mask", "graph_laplacian"):
        raise ValueError(f"method must be 'unsharp_mask' or 'graph_laplacian', got {method!r}")
    if method == "graph_laplacian" and weight_original != 1.0:
        raise ValueError(
            f"weight_original applies to the unsharp mask only, got {weight_original} with "
            "method='graph_laplacian'"
        )
    device = vertices.device
    n = vertices.size
    out = _launch.empty(n, dtype=wp.vec3, device=device)
    if n == 0:
        return out
    if method == "graph_laplacian":
        graph = laplacian_operator
        if graph is None:
            graph = laplacian.graph_laplacian(vertices, faces)
        step = wp.float64(weight)

        def graph_pass(_index: int, src: _Positions, dst: _Positions) -> None:
            _launch.launch(
                kernel_smoothing.GRAPH_SHARPEN_PASS[src.dtype, dst.dtype],
                dim=n,
                inputs=[graph.offsets, graph.columns, graph.values, src, step],
                outputs=[dst],
                device=device,
            )

        return _vec3_passes(vertices, max(iterations, 0), graph_pass, out=out)
    # No volume constraint on the inner smoothing: its rescaling would leak into the difference and
    # show up as a uniform scaling of the sharpened mesh rather than as detail. The smoothed
    # positions are ``filter_laplacian(lamb=1, volume_constraint=False)``'s, written into ``out``
    # and sharpened there in place.
    operator = laplacian_operator
    if operator is None:
        operator = laplacian.face_weighted_laplacian(vertices, faces)
    coeff = wp.float64(1.0)
    if iterations <= 0:
        _launch.map(
            kernel_smoothing.unsharp_step,
            vertices,
            vertices,
            wp.float32(weight),
            wp.float32(weight_original),
            out=out,
        )
        return out

    def sharpen_pass(index: int, src: _Positions, dst: _Positions) -> None:
        # The last pass applies the unsharp mask as it writes, so the smoothed field is not stored.
        if index < iterations - 1:
            _diffuse_pass(operator, coeff, src, dst)
            return
        _launch.launch(
            kernel_smoothing.SHARPEN_PASS[src.dtype],
            dim=n,
            inputs=[
                operator.offsets,
                operator.columns,
                operator.values,
                src,
                coeff,
                vertices,
                wp.float32(weight),
                wp.float32(weight_original),
            ],
            outputs=[dst],
            device=device,
        )

    _vec3_passes(vertices, iterations, sharpen_pass, out=out)
    return out
