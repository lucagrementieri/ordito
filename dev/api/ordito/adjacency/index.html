ordito.adjacency

Mesh face-adjacency graph: which faces share an edge, and what each adjacent pair looks like.

face_adjacency is the table every other function here reads: one row per edge-adjacent face pair. The rest are per-adjacency-row quantities over that table, all row-aligned with it, so a caller derives the pairs once and passes them in -- require_paired_adjacency states the one rule those keywords carry, and is public because the functions taking the pair span three modules.

  • face_adjacency_unshared gives the two opposite corners of each pair, and face_adjacency_angles the dihedral between the two faces.
  • face_adjacency_convex answers whether a pair is convex -- each face's third vertex on the inner side of the other's plane -- and face_adjacency_projections returns the signed distances it thresholds, for callers that want the margin rather than the verdict.

face_connected_component_labels is the one whole-graph answer: face-level connected components over the same adjacency.

def face_adjacency(
    faces: wp.array[wp.int32],
    *,
    return_edges: bool = False,
    n_vertices: int | None = None,
    edges_paired: bool = False,
) -> odt.Array2dInt32 | tuple[odt.Array2dInt32, odt.Array2dInt32]:
    """
    Face index pairs that share an undirected mesh edge.

    Each output row lists two face indices whose triangles share an edge (vertex
    pair). On a closed manifold mesh every interior edge appears exactly twice in
    the edge list, so only edges with duplicate sorted rows are kept—boundary edges
    that appear once are omitted.

    Parameters
    ----------
    faces
        ``(3 * n_faces,)`` buffer of triangle vertex indices, the same flat layout as
        [`ordito.triangles`][ordito.triangles] and
        [`faces_to_edges`][ordito.edges.faces_to_edges].
    return_edges
        If ``True``, also return the shared vertex indices for each adjacency row.
    n_vertices
        Optional vertex count, used as the row-hashing radix. It does not change the answer:
        when ``None`` a fixed radix above every ``int32`` index packs the edges instead, in the
        same order, so no reduction or host readback is needed either way. When given it must be
        greater than every index in ``faces``; see the warning on
        [`hash_indices_rows`][ordito.grouping.hash_indices_rows].
    edges_paired
        Promise that every undirected edge is shared by exactly two faces -- what
        [`is_edge_manifold`][ordito.validation.is_edge_manifold] with
        ``allow_boundary_edges=False`` establishes. The adjacency then has exactly
        ``3 * n_faces / 2`` rows and they are consecutive in the sorted edge-key order, so the
        run detection, its scan and the host read of the pair count are skipped. The answer is
        byte-identical to the default path on such a mesh. The promise is **not checked** beyond
        the face count's parity: on a mesh with a boundary or a non-manifold edge the rows are
        still valid face indices but pair faces that need not share an edge.

    Returns
    -------
    odt.Array2dInt32 or tuple of two such arrays
        ``(m, 2)`` **adjacency**, ``m`` the number of face pairs sharing an edge, on
        ``faces.device``. Row ``k`` gives face indices ``(f0, f1)`` with ``f0 <= f1`` (rows sorted
        in-place). Faces ``faces[3*f0:3*f0+3]`` and ``faces[3*f1:3*f1+3]`` share an edge.

        When ``return_edges`` is ``True``, also returns ``(m, 2)`` **adjacency_edges**
        with the sorted vertex pair for that shared edge (one row
        per adjacency pair, taken from the first matching edge row).

    Raises
    ------
    ValueError
        If ``edges_paired`` is given for an odd face count, where no pairing exists.

    Notes
    -----
    Duplicate-edge grouping uses
    [`group_int_rows`][ordito.grouping.group_int_rows] with
    ``length=2``, equivalent to [`trimesh.grouping.group_rows`][] with
    ``require_count=2``. An empty mesh yields shape ``(0, 2)``.

    See Also
    --------
    [`faces_to_edges`][ordito.edges.faces_to_edges]
    [`connected_component_labels_from_edges`][ordito.graph.connected_component_labels_from_edges]
    [`face_connected_component_labels`][ordito.adjacency.face_connected_component_labels]
    [`trimesh.graph.face_adjacency`][]

    Examples
    --------
    Two triangles sharing the edge ``(1, 2)`` give one row; on the closed cube every one of the 18
    edges joins two faces, so there are 18 rows:

    ```python
    import warp as wp

    import ordito as od

    faces = wp.array([0, 1, 2, 2, 1, 3], dtype=wp.int32)
    adjacency, shared_edges = od.adjacency.face_adjacency(faces, return_edges=True)
    print(adjacency.numpy().tolist(), shared_edges.numpy().tolist())  # [[0, 1]] [[1, 2]]
    vertices, faces = od.creation.box()
    print(od.adjacency.face_adjacency(faces).shape)  # (18, 2)
    ```
    """
    device = faces.device
    n_faces = faces.size // 3
    if n_faces == 0:
        empty_array = odt.empty_2d((0, 2), wp.int32, device=device)
        if return_edges:
            return empty_array, odt.empty_2d((0, 2), wp.int32, device=device)
        return empty_array

    if edges_paired and n_faces % 2 != 0:
        raise ValueError(f"edges_paired needs an even face count, got {n_faces} faces")
    # Edge ``e`` belongs to face ``e // 3``, so the owning faces need no ``edges_face`` table, no
    # gather through it, and no row sort — one kernel does the division and orders the pair. With
    # ``return_edges`` the same kernel writes each pair's shared edge too, straight off ``faces``,
    # so no edge table is built just to be gathered from. Unpaired, that kernel also compacts the
    # pairs off the sorted keys, so no intermediate group table is written.
    if edges_paired:
        edge_groups = _paired_edge_groups(faces, n_vertices)
        n_pairs = int(edge_groups.shape[0])
        kernel, dim, sources = kernel_adjacency.edge_pairs_to_face_pairs, n_pairs, [edge_groups]
    else:
        order, inclusive, n_pairs = _sorted_pair_scan(faces, n_vertices)
        kernel, dim = kernel_adjacency.emit_sorted_face_pairs, inclusive.size
        sources = [inclusive, order]
    adjacency = odt.empty_2d((n_pairs, 2), wp.int32, device=device)
    adjacency_edges = odt.empty_2d((n_pairs, 2), wp.int32, device=device) if return_edges else None
    if n_pairs > 0:
        _launch.launch(
            kernel,
            dim=dim,
            inputs=[faces, None, *sources, adjacency, adjacency_edges],
            device=device,
        )
    if adjacency_edges is None:
        return odt.as_array2d(adjacency, wp.int32)
    return odt.as_array2d(adjacency, wp.int32), odt.as_array2d(adjacency_edges, wp.int32)

Raise unless a precomputed face-adjacency pair is either wholly given or wholly omitted.

The contract behind every face_adjacency= / face_adjacency_edges= keyword in the package: the two tables are row-aligned halves of one answer and are useless apart, so a function that accepts them accepts both or neither. Public because the functions that take the pair live in three modules -- here, ordito.curvature and ordito.validation -- and they must all reject the same call with the same message; a caller that validates its own arguments before dispatching between them can use it for that too.

Call it before an empty-mesh guard, not after. A half-supplied pair is a caller bug whatever the mesh is, and the four wrappers that take the pair once disagreed about this, so the same wrong call raised or returned an empty answer depending on the input. The derivation goes the other way round -- below the guard -- because on an empty mesh face_adjacency would build two empty tables nothing reads.

vertex_face_adjacency 

vertex_face_adjacency(
    faces: array[int32], *, n_vertices: int | None = None
) -> tuple[wp.array[wp.int32], wp.array[wp.int32]]

Incidence CSR of the faces touching each vertex, as (vertex_faces, offsets).

Row v is vertex_faces[offsets[v] : offsets[v + 1]] and lists every face that references vertex v, once per reference. offsets has length n_vertices + 1, so its last entry is the total 3 * n_faces and no caller needs a sentinel appended. Values first and offsets second is the package's packed-buffer convention -- see array.pack_1d_arrays, which states it.

Built by counting sort rather than from halfedge twins, and that is a deliberate limitation rather than an omission: each row is a set, not a rotation. Ordering a row would require the halfedge structure, which does not exist at a vertex-non-manifold vertex — and the decimator and normal-flip guards that consume this must run on exactly such meshes. Use vertex_one_rings when the rotational order is what is wanted; it requires an edge-manifold mesh in exchange.

faces array[int32]

(3 * n_faces,) flat triangle index buffer.

 required
n_vertices int | None

Number of vertices, i.e. the number of CSR rows. When None it is inferred from faces with array.index_bound, which costs one host readback; pass it when the caller already knows it. Rows for vertices no face references come out empty.

 None

(3 * n_faces,) face indices, grouped by vertex. Under is_deterministic each row is in ascending face order, the same on every run; otherwise the order within a row is arbitrary.
offsets array[int32]

    rather than an omission: **each row is a set, not a rotation**. Ordering a row would require the
    halfedge structure, which does not exist at a vertex-non-manifold vertex — and the decimator and

    [`vertex_one_rings`][ordito.halfedge.vertex_one_rings] when the rotational order is what is

    faces
        ``(3 * n_faces,)`` flat triangle index buffer.

        Number of vertices, i.e. the number of CSR rows. When ``None`` it is inferred from

    -------

        ``(3 * n_faces,)`` face indices, grouped by vertex. Under
        [`is_deterministic`][ordito.config.is_deterministic] each row is in ascending face order,

        ``(n_vertices + 1,)`` row offsets on ``faces.device``.

    [`vertex_one_rings`][ordito.halfedge.vertex_one_rings]

    Examples
    --------
    Vertices 1 and 2 lie on the shared edge of two triangles, so they touch both faces:

    ```python
    import warp as wp

    import ordito as od

    print(sorted(vertex_faces.numpy()[offsets.numpy()[1] : offsets.numpy()[2]].tolist()))  # [0, 1]
    ```

        # would otherwise hand back an unwritten ``3 * n_faces`` buffer of allocator garbage.
        return (
            _launch.zeros(3 * n_faces, dtype=wp.int32, device=device),
            _launch.zeros(row_count + 1, dtype=wp.int32, device=device),
        )

    # A flat face buffer *is* the corner -> vertex map, so one launch over all 3 * n_faces corners
    # gives each vertex its incident-face count.
    _launch.launch(
        kernel_scatter.count_occurrences, dim=3 * n_faces, inputs=[faces, counts], device=device
    )
    return vertex_face_adjacency_from_counts(faces, counts)

    faces: wp.array[wp.int32], counts: wp.array[wp.int32]
) -> tuple[wp.array[wp.int32], wp.array[wp.int32]]:
    """
    [`vertex_face_adjacency`][ordito.adjacency.vertex_face_adjacency] from counts already taken.

    The second half of that function, for a caller whose own kernel visits every corner in a pass
    it makes anyway and counts each vertex's corners there: the corner histogram is the one launch

    rows are filled by atomics, their per-row cursor, so its contents are unspecified afterwards.

    Parameters
    ----------
    faces
        ``(3 * n_faces,)`` flat triangle index buffer, every index in ``[0, n_vertices)``.
    counts
        ``(n_vertices,)`` ``int32`` number of corners of ``faces`` naming each vertex, on
        ``faces.device``. Overwritten.

    Returns
    -------
    vertex_faces : wp.array[wp.int32]
        ``(3 * n_faces,)`` face indices grouped by vertex, ordered as in
        [`vertex_face_adjacency`][ordito.adjacency.vertex_face_adjacency].
    offsets : wp.array[wp.int32]
        ``(n_vertices + 1,)`` row offsets on ``faces.device``.

    Raises
    ------
    RuntimeError
        If ``faces`` and ``counts`` are not on one device.

    See Also
    --------
    [`vertex_face_adjacency`][ordito.adjacency.vertex_face_adjacency]
    [`ordito.graph.edges_to_neighbor_lists_from_counts`][ordito.graph.edges_to_neighbor_lists_from_counts]
        The same split for an edge list's neighbour lists.

    Examples
    --------
    ```python
    import warp as wp

    import ordito as od

    faces = wp.array([0, 1, 2, 2, 1, 3], dtype=wp.int32)
    counts = wp.array([1, 2, 2, 1], dtype=wp.int32)
    vertex_faces, offsets = od.adjacency.vertex_face_adjacency_from_counts(faces, counts)
    print(offsets.numpy().tolist())  # [0, 1, 3, 5, 6]
    print(sorted(vertex_faces.numpy()[offsets.numpy()[1] : offsets.numpy()[2]].tolist()))  # [0, 1]
    ```
    """
    require_same_device(faces=faces, counts=counts)
    device = faces.device
    n_faces = faces.size // 3
    row_count = counts.size
    offsets = _launch.zeros(row_count + 1, dtype=wp.int32, device=device)
    if n_faces == 0 or row_count == 0:
        return _launch.zeros(3 * n_faces, dtype=wp.int32, device=device), offsets
    vertex_faces = _launch.empty(3 * n_faces, dtype=wp.int32, device=device)
    # Deliberately NOT od.array.counts_to_offsets: that helper always reads the total back, and
    # this function never needs it (it is 3 * n_faces, known on the host). Converting for
    # symmetry would add a device synchronization where there is currently none.
    tail = _launch.view(offsets, 1, row_count + 1)
    _launch.array_scan(counts, out_array=tail, inclusive=True)
    if is_deterministic():
        # The stable sort of the face buffer lists each vertex's corners in ascending order, so its
        # permutation's faces are the rows in ascending face order: the same on every run, where
        # the scatter below fills each row in the order its atomics commit.
        _, corner_order = od.array.sort_and_argsort(
            faces, end_bit=max(1, (row_count - 1).bit_length())
        )
        _launch.map(kernel_adjacency.corner_face, corner_order, out=vertex_faces)
        return vertex_faces, offsets
    # The counts are spent once scanned, so their buffer becomes the scatter's per-row cursor,
    # counting each row's free slots down to zero: no second buffer and no re-zeroing.
    _launch.launch(
        kernel_adjacency.scatter_vertex_faces,
        dim=n_faces,
        inputs=[faces, offsets, counts, vertex_faces],
        device=device,
    )
    return vertex_faces, offsets

    n_vertices: int | None = None,

    """
    Vertex on each adjacent face that is not on their shared edge.

    For each row of ``face_adjacency``, column 0 is the unshared vertex index on
    the first face and column 1 on the second face. When a face does not have

    Parameters
    ----------
    faces
        ``(3 * n_faces,)`` buffer of triangle vertex indices, the same flat layout as
        [`face_adjacency`][ordito.adjacency.face_adjacency].

        is materialized.

        [`face_adjacency`][ordito.adjacency.face_adjacency] with ``return_edges=True``), or
        ``None``. Must be supplied together with ``face_adjacency`` or omitted with it.

        Optional vertex count used as the row-hashing radix, forwarded to
        [`face_adjacency`][ordito.adjacency.face_adjacency]. Ignored when the adjacency tables are
        supplied. It does not change the answer; see that function's note.

    Returns
    -------
    odt.Array2dInt32
        ``(m, 2)`` unshared vertex indices per face pair, on ``faces.device``. Row ``k`` gives
        vertex indices into
        ``faces`` for the corners not on ``face_adjacency_edges[k]``, or ``-1``
        when degenerate. Rows are in the same order
        [`face_adjacency`][ordito.adjacency.face_adjacency] returns for the same ``faces``, so the
        two line up row-for-row whether or not the tables were passed in.

    Raises
    ------
    ValueError
        If only one of ``face_adjacency`` and ``face_adjacency_edges`` is provided,
        or if their row counts differ.
    RuntimeError
        If ``faces``, ``face_adjacency`` and ``face_adjacency_edges`` are not all on one device.

    See Also
    --------
    [`face_adjacency`][ordito.adjacency.face_adjacency]
    [`trimesh.graph.face_adjacency_unshared`][]

    second:

    ```python
    import ordito as od

    print(od.adjacency.face_adjacency_unshared(faces).numpy().tolist())  # [[0, 3]]
    ```

        faces=faces, face_adjacency=face_adjacency, face_adjacency_edges=face_adjacency_edges
    )

    # owning faces and the shared edge from the sorted halfedge pairs instead. Only the pairing
    # rule is shared with the other wrappers that take this pair.
    require_paired_adjacency(face_adjacency, face_adjacency_edges)
    device = faces.device
    # Both branches end in one launch over ``m`` adjacency rows writing one ``(m, 2)`` buffer, so
    # the two differ only in the kernel and the table it reads. Resolving that first, and letting a
    # single ``m == 0`` return cover an empty mesh, an empty adjacency and an empty supplied table
    # alike, is what keeps the empty case to *one* allocation rather than building an empty
    # ``edge_groups`` only to size an empty output off it.

            (face_adjacency, face_adjacency_edges),

    if m > 0:
        _launch.launch(kernel, dim=dim, inputs=[faces, *tables, unshared], device=device)
    return odt.as_array2d(unshared, wp.int32)

def sorted_face_edge_keys(
    faces: wp.array[wp.int32], *, n_vertices: int | None = None
) -> tuple[wp.array[wp.uint64], wp.array[wp.int32]]:
    """
    Every halfedge's undirected edge key, sorted, and the permutation that sorted them.

    Halfedge ``3f + k`` is corner ``k`` of face ``f``, the
    [`faces_to_edges`][ordito.edges.faces_to_edges] row order, and its key packs the sorted
    endpoint pair ``(lo, hi)`` as ``lo + hi * radix`` -- the key
    [`hash_indices_rows`][ordito.grouping.hash_indices_rows] gives those rows. The sort is stable,
    so equal keys keep halfedge order: an edge's halfedges are one run, the pairs
    [`face_adjacency`][ordito.adjacency.face_adjacency] groups are its runs of exactly two, and
    ``order[i] // 3`` is the face owning sorted position ``i``.

    Parameters
    ----------
    faces
        ``(3 * n_faces,)`` flat triangle index buffer.
    n_vertices
        Optional exclusive bound on the vertex indices, used as the packing radix. It lets the sort
        order only the low bits the keys can occupy, which is cheaper; without it the keys pack
        against [`constants.INDEX_RADIX_PAIR`][ordito.constants.INDEX_RADIX_PAIR], which orders
        them identically and needs no bound. It is trusted, not checked.

    Returns
    -------
    sorted_keys : wp.array[wp.uint64]
        ``(3 * n_faces,)`` ascending keys.
    order : wp.array[wp.int32]
        ``(3 * n_faces,)`` halfedge index of each sorted key.

    Raises
    ------
    ValueError
        If ``n_vertices`` is not positive.

    Examples
    --------
    With ``n_vertices=4`` an edge ``(lo, hi)`` packs as ``lo + 4 * hi``; the two halfedges of the
    shared edge ``(1, 2)`` (halfedges 1 and 3) sort next to each other:

    ```python
    import warp as wp

    import ordito as od

    faces = wp.array([0, 1, 2, 2, 1, 3], dtype=wp.int32)

    print(sorted_keys.numpy().tolist())  # [4, 8, 9, 9, 13, 14]
    print(order.numpy().tolist())  # [0, 2, 1, 3, 4, 5]
    ```
    """
