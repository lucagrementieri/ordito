The site nav, read by literate-nav. The guide pages are hand-written under docs/; the API pages
are generated by the api-autonav plugin (mkdocs.yml), one per public module, at
api/triwarp/<module>.md. The plugin nests them by package, which for a flat package is one
alphabetical list, so the themed shelving below is authored here. Order within a section is the
nav order. Every public module must appear exactly once: a module missing from this file is still
built but unreachable from the nav, and tests/api_conventions.py check 28 fails on it.

Shelving decisions that are not obvious from the section titles:
- visibility is under Measures rather than a query heading: ambient_occlusion, shape_diameter and
  thickness are per-point scalar shape descriptors, which is how pymeshlab files them.
- Mesh editing opens with transform (the simplest edit, and one every other member leaves
  invariant) and closes with levelset (the one member that resamples the surface).
- voxels sits with points and sample, not the spatial queries: points.farthest_point_sample and
  voxels.voxel_down_sample are the package's two point-cloud down-samplers.
- energies follows laplacian: the two halves of one subject (cotmatrix, crouzeix_raviart_*).
- geodesic_walk is shelved with heat, so both geodesic entry points are found together.
